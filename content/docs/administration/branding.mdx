**Appearance & features → Branding** (`/admin/branding`). The instance name, a short name, a logo, the appearance, and a message on the sign-in page.

<Screenshot slot="admin-branding" />

## Name and logo

- **App name** (up to 80 characters) is shown on the sign-in page, in the app's navigation, in browser tab titles, on share pages and in emails ([below](#what-follows-branding)).
- **Short name** is used in the narrow sidebar; when blank, a name longer than 20 characters collapses to its initials.
- **Logo file** or **Logo URL**. A **Live preview** beside the form shows the sign-in page as it will look.

**Upload the logo rather than linking it.** The logo URL field accepts an external `http(s)` address, but a linked image disappears if its host does, on the one page people see before they can sign in. Uploading stores it with the instance and fills in the field.

**SVG uploads are refused**: the logo renders before sign-in, and SVG can carry script. PNG, JPEG and WebP are accepted, checked by content rather than extension, up to 1 MB.

Without a logo, headers show the Open Chat Interface mark beside the app name. With a logo, the logo replaces both the mark and the name.

## Appearance

- **Accent color**: **neutral** (the default), **blue**, **violet** or **emerald**, applied to buttons, links and highlights across the instance, including the sign-in and share pages. Surfaces stay neutral, so no choice here can make text unreadable.
- **Default theme**: **light**, **dark** or **system**, for anybody who has not chosen a theme themselves. People who chose one keep it.

## Language

Under the appearance settings, with its own **Save language** button. Added in v0.14.

- **Languages people can choose**: English is always on. **Español** and **العربية** are machine-drafted and marked **(beta)**: nobody who reads them has reviewed them yet, and they can contain mistakes. They are off until you turn them on; turn one on once someone who reads it has looked it over. The project's `docs/dev/translations.md` describes how a reviewer works through a catalog.
- **Default language**: what people get who have not chosen their own. It must be one of the enabled languages. **Follow the browser** uses the first of a person's browser languages that is turned on, else English.

People choose their own language under Settings → Customization, and that choice wins over the default. Arabic is shown right to left across the whole app, administration pages included, though their text stays English. Switching a language off does not delete anyone's choice: they see the default until it is switched on again. The sign-in page follows the default or the browser.

**The administration console stays in English** whatever is chosen here, and so does what the server writes: emails, exported files, audit entries and the text of API errors. Model names and the branding text you set (the app name, the sign-in message) are shown as you wrote them. A change is audited as `settings.update` with the languages it was and became (`language.enabled`, `language.default`).

## What follows branding

| Surface | Name | Logo | Colours |
|---|---|---|---|
| Sign-in, sign-up, invitation and password-reset pages | Yes | Yes | Yes |
| Sidebar and the phone menu | Yes (or the short name) | Yes | Yes |
| Browser tab | Title: *page · name*, such as *Sign in · Example University Chat*; a shared conversation shows its title | Tab icon, from an uploaded logo | |
| Installed app (home screen or desktop) | Name, and short name (at most 12 characters) | Icon, when the logo is a square PNG of at least 512 px | Title-bar and splash colours |
| Shared conversation pages | Header | Header | Yes |
| Verification, password-reset and invitation emails | Subject, body and the sender's display name | | |
| Scheduled usage reports | Subject and body | | |
| Diagrams the assistant draws | | | Accent (below) |
| Markdown download of a conversation | *Exported from Example University Chat on …* | | |
| Word, PDF, PowerPoint and Excel files | Author or creator | | |

**Diagram accent.** Diagrams are drawn on light paper, so each colour theme uses its light-mode accent. Neutral has no hue, so it keeps the diagram style's default orange.

**Tab icon.** An uploaded logo becomes the tab icon (and the home-screen icon on iOS), scaled by the browser, so a square logo works best. A logo linked from another site keeps the Open Chat Interface icon, so browsers never fetch a third-party image for every tab.

**Installed app.** The instance serves a web app manifest at `/api/manifest.webmanifest`, so people can add OCI to a phone's home screen or a computer's desktop ([Installing the app](/docs/using/installing-the-app)). It is public, like the sign-in page, and contains only the name, colours and icon addresses; nothing else from Branding or from the instance is in it. Browsers may keep it for five minutes and decide for themselves when to look again, so a change reaches an installed app after a while. An iPhone or iPad copies the name and icon when the app is added, so people there add it again.

- **Name.** The app name; the short name, or the first 12 characters of the name when there is none, is what phones show under the icon.
- **Colours.** The splash screen is the page colour of the default theme (light, or dark for dark and system: a manifest is the same for every visitor and cannot follow a person's device). The title bar takes the accent of a blue, violet or emerald colour theme, and the page colour for neutral, which has no hue.
- **Icons.** The bundled OCI icons, unless you have uploaded a logo that is a **PNG, square, and at least 512 px on a side**; then that logo is the app's icon. A JPEG, a WebP, a PNG that is smaller or not square, a logo linked from another site and a logo that cannot be read all keep the bundled icons. Nothing breaks and nothing tells you, so check the app's icon after changing the logo. A logo with transparent corners is drawn on the launcher's own background, so give it a solid or padded background if it looks bare. iPhones and iPads use the home-screen icon instead (any uploaded logo type), and the OCI icon when there is no logo.
- **No offline mode.** OCI never stores pages or conversations on a device for offline use, and registers no service worker. If you run your own proxy, see [The installable app](/docs/self-hosting/reverse-proxy#the-installable-app).

What does not follow branding:

- The page served before the app starts, for the moment it takes to load, and so **link previews**: chat apps and search engines read that page without running the app, so a shared link's preview says *Open Chat Interface*.
- The Open Chat Interface mark itself, which is never recoloured.
- The README in a person's data export, which names the software and version that wrote it, since an import needs that.
- The client name OCI registers with a connector's sign-in server, which may show *Open Chat Interface* on its consent page.
