Open Chat Interface (OCI) is an open-source (MIT) chat application that an institution runs for its own people: a university, a research organisation or a company. Everyone signs in with the institution's identity provider and chats with the models the institution has approved, from several providers, in one interface.

Administrators decide what happens: which models each role can use, how much each person may spend, which features are on, how long conversations are kept, and who can read the audit log. People get a familiar chat app with projects, artifacts, tools, memory and their own data export.

## How it is built

OCI has two parts, published as two container images:

- **API** (`ghcr.io/ncecere/open-chat-interface/api`): a Node.js service that does all the work: sign-in, chat, files, administration and background jobs.
- **Web** (`ghcr.io/ncecere/open-chat-interface/web`): the browser app, served by Caddy, which also forwards `/api` to the API so everything is on one origin.

It stores everything in **PostgreSQL 17**, uses **Redis** for resumable replies and shared rate limits, and keeps files on a local volume or in **S3-compatible storage**. Almost everything is configured in the admin dashboard; environment variables cover only what must exist before the database can be read. See [Self-hosting](/docs/self-hosting).

## Accessibility

The interface targets **WCAG 2.2 Level AA**. Automated accessibility checks run on desktop and phone layouts for sign-in, chat, settings, administration, share pages and dialogs, together with checks from a manual keyboard pass: a skip link, a visible focus indicator on every control, and dialogs that return focus to whatever opened them. Automated checks are a regression net, not a full conformance assessment.

## Project status

OCI is **pre-1.0**. These docs describe **v0.9.1**; see [Releases](/docs/releases) for what changed and how to upgrade. What to expect:

- Releases are frequent, and each one's notes say what to do when upgrading.
- Database migrations are forward-only. Rolling back past a migration means restoring a backup.
- There is **no public API** for scripts or integrations, and a personal-key API is not planned: OCI is a chat interface. Integrations that need model access should go through a model gateway such as LiteLLM.
