Put a TLS-terminating reverse proxy or load balancer in front of the **web** container (port 8080). The web container's Caddy does the rest: it serves the app, forwards `/api/*` to the API, and sets security headers. `APP_URL` must be the public `https://` address.

Requirements for your proxy:

- **Do not buffer responses.** Replies stream; a buffering proxy holds them back until they finish. Disable response buffering for `/api/*` (in nginx, `proxy_buffering off;`).
- **Allow long requests.** A reply can stream for minutes. Raise read timeouts accordingly.
- **Allow large uploads**: files up to your upload limit (20 MB by default) and imports up to `IMPORT_MAX_UPLOAD_BYTES` (512 MB by default).
- **Set `TRUSTED_PROXIES`** on the web container to your proxy's addresses, so OCI records each person's own address rather than the proxy's. See [below](#behind-another-proxy-or-an-ingress).
- **Send everything through the web container.** Do not route `/api` straight to the API service around it: the API then has no trustworthy client address to record.
- **Do not forward `/metrics`.** It is served by the API, not the web container, and should be scraped from inside your network.

## Behind another proxy or an ingress

OCI records a client address on sessions (a person's active sessions under **People**) and in the audit log, and the [sign-in limit](/docs/administration/budgets-and-limits#sign-in-attempts) counts attempts per address. The web container's Caddy decides that address and passes exactly one to the API, as `X-Forwarded-For`; the API believes nothing else. Caddy also drops `X-Real-IP`, `CF-Connecting-IP`, `True-Client-IP` and `Forwarded`, so a client cannot choose its own address by sending them.

By default Caddy trusts nothing in front of it, so the address is whatever connected to the web container. Exposed directly, that is the client. Behind a load balancer, another reverse proxy or a Kubernetes ingress, it is that proxy, so everybody appears to come from one address and shares one address limit for failed sign-ins.

Set `TRUSTED_PROXIES` on the **web** container to the addresses of the proxies in front of it, separated by spaces (not commas). Each entry is an IP address or a CIDR range; `private_ranges` stands for all private and loopback ranges:

```sh
# docker/.env
TRUSTED_PROXIES=10.0.0.0/8 192.168.10.5
```

Caddy then reads `X-Forwarded-For` from those proxies right to left, skipping trusted hops, and the first address that is not trusted is the client. A value a client put at the left of the header is never reached. Requests from any other address ignore the header.

- Trust only addresses that really are your proxies, and make sure each one sets or appends `X-Forwarded-For`. Most do by default; nginx needs `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`.
- In Kubernetes, use the ingress controller pods' range, or the cluster's pod CIDR.
- A proxy that replaces the client address entirely (a TCP load balancer without the PROXY protocol) cannot be recovered from; use the load balancer's HTTP mode.
- The bundled Compose file passes `TRUSTED_PROXIES` through to the web container. Elsewhere, set it as an environment variable of the web image. The API has no such setting.

After deploying, sign in and check the address on your own session under **People**, or in the audit log.

<Callout title="Changed in v0.9.2">
  Before v0.9.2 the web container passed `CF-Connecting-IP` and `X-Real-IP` from the browser through to the API, which trusted them, so any client could choose the address it was recorded and rate-limited under. Upgrade to v0.9.2 or later. See [v0.9.2](/docs/releases/v0-9-2).
</Callout>

## Health checks and draining

From v0.11 an API replica that is stopped [drains](/docs/self-hosting/upgrades#replacing-replicas-draining): `/api/health/ready` answers `503` at once, new chat turns are refused with `503`, and replies in progress finish for up to `SHUTDOWN_DRAIN_TIMEOUT_MS` (25 s). The bundled web container's Caddy handles this by itself. If a proxy or load balancer of yours health-checks or balances OCI's containers:

- **Health checks**: point active checks at `/api/health/ready` with a short interval (2 to 5 seconds) and one failure to mark a target down. HAProxy: `option httpchk GET /api/health/ready` with `default-server inter 2s fall 1 rise 2`. AWS ALB: the same path, and a deregistration delay of at least `SHUTDOWN_DRAIN_TIMEOUT_MS`, so the balancer does not cut replies in progress.
- **Keep-alive**: keep the proxy's idle timeout for upstream connections below 65 seconds, the API's keep-alive (nginx `keepalive_timeout` in the `upstream` block, HAProxy `timeout http-keep-alive`).
- **Retries**: retrying a failed *connection* on another target is safe for every method. A drain refusal (`503` with the header `X-OCI-Draining: 1`) is also safe to retry, since the API refuses it before reading it; the web app retries it itself, so a proxy need not.
- **Streaming**: keep response buffering off for `/api`, as above.

The API answers `503` only when a replica cannot serve: it is draining, or (readiness only) its database has been unreachable for more than 30 seconds. A request that fails because a database connection dropped answers `500` marked retryable instead, so a database failover does not take every replica out of rotation at once.

## The headers OCI sends

Every response from the web container, except one path, carries:

```text
Content-Security-Policy: default-src 'self'; connect-src 'self'; img-src 'self' data: blob: https:; style-src 'self' 'unsafe-inline'; font-src 'self' data:; script-src 'self'; manifest-src 'self'; worker-src 'self' blob:; object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'self'
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Cross-Origin-Opener-Policy: same-origin
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()
```

Add `Strict-Transport-Security` at your TLS proxy.

## The artifact frame

HTML and SVG [artifacts](/docs/using/artifacts) run in a sandboxed frame loaded from **`/artifact-frame.html`**, a static file of the web image, with `sandbox="allow-scripts"` and no `allow-same-origin`, so it has an opaque origin. It is the one page OCI frames itself, so it gets its own policy instead of the one above:

```text
Content-Security-Policy: sandbox allow-scripts; default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; base-uri 'none'; form-action 'none'; frame-ancestors 'self'
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), display-capture=()
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Cache-Control: no-cache
```

and **no** `X-Frame-Options: DENY`.

<Callout type="warn" title="If your proxy adds headers to every response">
  A proxy that adds its own `Content-Security-Policy` or `X-Frame-Options` to every response must exempt `/artifact-frame.html`, and send the policy above for it, including `sandbox allow-scripts` and `frame-ancestors 'self'`. Otherwise artifact previews stay blank (the rest of OCI is unaffected). The page also protects itself: it writes nothing unless it is framed with an opaque origin, so a proxy that sends no policy for it cannot make it run code on OCI's origin.
</Callout>

For example, in nginx, where your server block adds headers:

```nginx
location = /artifact-frame.html {
    proxy_pass http://oci_web;
    # Let the web container's own headers for this path through unchanged:
    # do not add X-Frame-Options or a Content-Security-Policy here.
}
```

## The installable app

From v0.14 people can install OCI to a home screen or desktop ([Installing the app](/docs/using/installing-the-app)). It adds no service and no setting. The instance serves a manifest at `/api/manifest.webmanifest`, and there is no service worker, so nothing of OCI is kept on a device for offline use: with the network down an installed app shows the browser's own error.

The bundled Caddy configuration (`docker/Caddyfile`, which the Helm chart's web pods run too, so the chart needs no change) already does what this needs. If you front OCI with your own proxy, or replace the web container, do the same:

- **Let the manifest through, unauthenticated.** `GET /api/manifest.webmanifest` must reach the API without a login or an access-control page in front of it (a browser fetches it without cookies), and keep its `Content-Type: application/manifest+json` and `Cache-Control: public, max-age=300`. Behind a single-sign-on proxy that redirects anonymous requests, the manifest is redirected too, and the browser then offers no install.
- **Allow it in the Content-Security-Policy.** The shipped policy names `manifest-src 'self'`. A policy that sets `manifest-src` or `default-src` to something narrower stops the browser reading the manifest.
- **Revalidate the pages.** Every page is `index.html`; send `Cache-Control: no-cache` for it under every path (`/`, `/auth/login` and the rest), not only `/index.html`, and for the files in `/icons/`. Files in `/assets/` have hashed names and may be cached for a year. Without this a browser may reuse its copy of the page by heuristic freshness, so an installed app opened offline can show an old page rather than the browser's error, and after an upgrade a page that points at assets that are gone. The bundled Caddy configuration did not send it for pages other than `/index.html` before v0.14.
- **Serve `/icons/*.png` as `image/png`** from the web container's files.

## Identity providers on private networks

If your OIDC identity provider is on a private network, list its origin in `AUTH_TRUSTED_ORIGINS`, or discovery is refused. See [Configuration](/docs/self-hosting/configuration#server).
